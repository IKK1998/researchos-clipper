# ResearchOS Clipper

把微信公众号文章保存到自己的 ResearchOS：复制链接、按快捷键，自动获取真实标题。
标题采集不使用大模型，不要求先下载正文，也不需要语雀会员。

[下载发布包](https://github.com/IKK1998/researchos-clipper/releases) ·
[验证记录](VERIFICATION.md) · [隐私说明](PRIVACY.md) · [MIT 许可证](LICENSE)

## 它解决什么问题

服务器直接访问公众号链接时，可能得到验证页而不是文章。
Clipper 改用用户授权的浏览器打开文章，读取与该链接对应的真实标题，
再回填到同一条收藏。它不是微信客户端插件，也不是独立的文献管理服务器。

当前提供以下入口：

| 入口 | 使用场景 | 当前验证范围 |
| --- | --- | --- |
| Mac 快捷键版 0.6.0 | 在微信阅读，复制链接后按 Option+S | 已完成真实收藏、标题回写、关键词检索和 Hammerspoon 重启恢复验证 |
| 浏览器扩展 0.6.1 | 使用已登录的公网 ResearchOS，不依赖本机 SSH 网关 | Chromium 隔离测试通过；真实公网登录、Windows/Edge 实机验收待完成 |
| iPhone 快捷指令 | 系统分享或复制链接 → 手机收藏页确认 | 静态页面已在维护者 FDU 部署，实际去重/回读/检索通过；iPhone安装与微信分享实测待完成 |
| 手机小程序开发版 | 微信复制链接 → 小程序粘贴收藏 | 配对、设备隔离和回读测试通过；未注册、未实机验收、未发布 |

浏览器包请使用 **v0.6.1**。v0.6.0 扩展存在参数序列化问题，已被后续版本修复。
两个入口的快捷键不同；不需要同时安装。尚未上架 Chrome/Edge 扩展商店。

新增 [`mobile/`](mobile/) 为手机公众号接收模块（开发预览），与电脑端共用仓库。
**尚未配置真实公众号或上线手机转发**。配置和限制见下面“手机微信转发收藏”。

## 自动标题如何工作

本节描述电脑端采集。手机开发版不具备电脑浏览器采集能力，见下面说明。

1. 收到你明确选择的公众号链接，先保存链接与待处理任务。
2. Mac 版在专用 Chrome 窗口打开文章；扩展读取用户选择的文章页面标题元数据。
3. 核对文章链接与收藏来源，拒绝验证页、占位标题和不匹配的页面。
4. 通过 ResearchOS 的标题采集接口回填标题，再读取服务器记录确认。
5. 成功后关闭 Mac 工具自己打开的窗口；已有标题不主动覆盖。

断网任务保存在本机队列中，连接恢复后继续处理。网站需要自行刷新列表或实现
自动刷新；Clipper 不会修改网站前端。保存链接、取得标题、取得正文、生成摘要
是四个不同状态，不能用其中一个状态代替其他状态。

## iPhone 快捷指令：无需注册公众号或小程序

手机用 Safari 打开 [手机收藏页](https://researchos.cacdb.org/phone-collect/index.html)，
用原来的授权账号登录，点击底部“下载 iPhone 收藏快捷指令”。
文件已通过 Apple 官方 `shortcuts sign --mode anyone` 签名，不包含 API Token、
SSH 凭据或个人收藏。安装完成后名称可能显示为 **ResearchOS-Collect**，可自行改名。

两种使用方式：

1. 有系统分享菜单：选择快捷指令 → 链接填入网站 → 点击“确认收藏”。
2. 微信没有系统分享菜单：文章菜单“复制链接” → 运行快捷指令 → 确认收藏。
   可将它添加到主屏幕或小组件，不需要打开电脑。快捷指令没有输入时读取当前
   剪贴板，有分享输入时使用分享内容；不后台读取、不监控剪贴板历史。

首次安装、剪贴板许可与网站登录由手机用户操作。安装文件只完成签名，
**还没有用维护者的真实 iPhone 完成安装/分享/剪贴板/重启验收**。
如果平台不允许从下载文件直接导入，可把仓库 `ios/ResearchOS-Collect.shortcut`
保存到“文件”App后打开；不要假定所有 iOS 版本的导入入口完全相同。
Safari 登录后如链接丢失，重新运行快捷指令或在收藏页长按粘贴。

### 安全、保存状态和重启

- 只有在网站点“确认收藏”才发送 POST；打开网址、分享预览不产生收藏。
- 文章链接通过 URL fragment 带入页面，不进入服务器请求 URL；页面填入后清掉
  fragment，只在该浏览器标签页 sessionStorage 留断网草稿，不写 Cookie 或后台密钥。
- 页面使用现有同源 `/api/v1/intake` 和来源回读接口，保留网站 Access 保护。
  不新增公开机器接口，不安装公众号接收服务，不部署小程序。
- 此入口 `ai_consent=false`，不自动产生付费模型调用。不会承诺抓到受限的标题/正文。
  已保存回执、来源回读、真实标题分别提示；网络失败不冒充保存成功。
- 换手机可重新安装同一文件并登录网站，不靠 Mac 隧道或 Hammerspoon。
  重启 iPhone 后无需启动桌面程序，但网站和手机网络仍须可用；重启实测待完成。
  sessionStorage 是临时草稿，不保证手机重启后仍保留，请保留尚未提交的原链接。

## 手机小程序开发版（已暂停上线，保留源码）

[`miniprogram/`](miniprogram/) 可导入微信开发者工具，与桌面版共用仓库。
**只有公众号不等于已有小程序**。需要你自行注册小程序账号，完成平台要求的
主体/备案/审核，取得小程序 AppID。不要发送或提交 AppSecret。
`project.config.json` 的 `touristappid` 仅为开发占位符，不能发布或代替实机验收。

操作路径：微信文章菜单“复制链接” → 打开收藏小程序 → “粘贴链接” → 收藏。
不是任意文章的系统转发接收器，不会读取点赞、聊天、微信收藏或剪贴板历史。

### 上线顺序

1. 用自己的 AppID 导入 `miniprogram/`，配置平台隐私声明及剪贴板用途。
2. 管理员先只读审计远程目录、空间、服务和恢复路径，再部署
   `mobile/miniprogram-server.js`。参考 `mobile/mini-config.example.env` 创建私有配置。
   ResearchOS 后台 API 密钥仅存服务器，不进入小程序包。
3. 服务仅监听 `127.0.0.1:8792`。为 `/v1/pair`、`/v1/collect`、`/v1/recent`
   设置单独 HTTPS 入口，并在代理限制请求大小/连接数/速率；不要公开上游 API。
   **不取消网站 Cloudflare Access 保护**。机器入口不能返回网页登录重定向。
4. 把 HTTPS 根地址填入 `miniprogram/config.js` 的 `apiBase`，在小程序后台配置
   request 合法域名，保持域名校验开启。
5. 在加载私有环境变量的服务器终端执行以下命令，私下将配对码交给手机用户：

   ```sh
   node mobile/miniprogram-server.js issue-code
   ```

   码有效 10 分钟、仅用一次。手机设备凭据有效 30 天，服务器仅保存其哈希。
   换手机需新配对码；不要把码或凭据写进公开日志。
6. 手机验收：配对 → 收藏真实文章 → 刷新状态 → 网站按链接/标题搜索 → 断网重试
   → 撤销设备。完成后才申请体验版/发布。

启动：`npm run start:mini`；常驻模板见 `mobile/mini-receiver.service.example`（未安装）。
队列存远程持久化目录，服务重启读回原队列。正常退出释放锁；原 PID 确认已死时
自动恢复运行锁。异常残留 `mini-start.lock` 需管理员核验，不能删除活跃实例的锁。
开机启动仍需管理员配置与验收，不依赖本地 Mac 常开。

### 状态与限制

- 先显示“已接收，等待入库”；来源 ID、原链接和标题回读一致才显示标题已入库。
  没标题时明确显示“链接已入库，标题待获取”。普通手机复制链接通常不带标题，
  本模块依赖网站已有标题流程，**不保证绕过微信限制取得标题或正文**。
- 所有提交 `ai_consent=false`，不调用计费模型。不改变网站原认证、数据库结构。
- 手机保留最多 20 条断网草稿，用户点击重试；页面打开或手动刷新查询本设备
  最近 10 条回执，不列出其他设备的收藏。退出设备不删除网站文章。
- 服务瞬时故障最多尝试 3 次；已得到来源 ID 后不重发入库请求。
- 全局每分钟最多 240 个请求/30 个配对请求；队列最多 1,000 条，设备/配对文件
  最多 2,000 条，满后拒绝新增，不自动删除。管理员需备份、归档和设置保留期限。
- 撤销：`node mobile/miniprogram-server.js revoke <device-hash>`。
  哈希来自私有队列 `device-*.json` 的文件名；撤销后不能提交或读取回执。

`npm test` / `npm run test:mini` 使用模拟上游与客户端；通过不等于微信工具编译、
真实手机授权或生产部署通过。

## Mac 安装：复制链接 + Option+S

准备：

- 官方 [Hammerspoon](https://www.hammerspoon.org/)。
- Google Chrome、Python 3。
- 一个已经授权的 ResearchOS 本机网关，例如 `http://127.0.0.1:3010`。
  SSH 隧道、服务器和认证由你自己的环境提供，本仓库不安装或绕过这些保护。

下载仓库后，进入仓库目录：

```sh
git clone https://github.com/IKK1998/researchos-clipper.git
cd researchos-clipper
python3 install-macos.py --login --dry-run
python3 install-macos.py --login
```

第一条安装命令只显示计划，不修改配置。正式安装会备份旧文件，更新三个 Spoon
文件，并只合并 ResearchClipper 的配置块，不覆盖其他 Hammerspoon 配置。

安装后：

1. 在 Hammerspoon 菜单选择 **Reload Config**。
2. 首次按系统提示授予辅助功能权限，以及 Hammerspoon 控制 Chrome 的自动化权限。
3. 在微信文章菜单选择“复制链接”，按 **Option+S**。
4. 等待“已自动保存标题”提示，再到 ResearchOS 的资料库按标题关键词搜索。

新安装的安装器默认使用 Option+S；已有快捷键、网关地址和 AI 设置会保留。
[config.example.lua](config.example.lua) 是手动配置示例，使用的是
Control+Option+Command+S；采用该示例时不要误以为快捷键是 Option+S。

快捷键冲突时，修改私有 `~/.hammerspoon/init.lua` 中的 `mods`、`key`，
再 Reload Config。不要将自己的凭据或 SSH 配置提交到这个仓库。

## 浏览器扩展：使用公网入口（预览）

推荐从 Releases 下载 `researchos-clipper-browser-v0.6.1.zip` 并解压；
源码用户也可以直接使用仓库的 `extension/` 目录。

1. 在浏览器打开并登录你有权限使用的 ResearchOS 网站。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启开发者模式，选择“加载已解压的扩展程序”，选中包含
   `manifest.json` 的扩展目录，不是整个仓库。
4. 点击扩展图标，粘贴公众号链接；粘贴后自动加入队列。
   已经在浏览器中阅读文章时，可以用 **Alt+Shift+S** 收藏当前文章。
5. 使用自己的部署时，在扩展设置中填写 HTTPS 根地址，并批准对应域名的权限。

扩展通过已登录网站页面发起正常的同源请求，不提取或导出登录 Cookie，
不需要你提供 SSH 密钥或 API Token。退出登录后会等待重新登录。
真实部署必须先完成一次“收藏 → 标题回读 → 关键词检索”的验收，
不能把隔离测试通过当成公网一定可用。

## 旧链接、分类与模型整理

**旧的无标题链接可以补标题，但工具不会自动扫描网站的全部历史收藏。**

重新复制同一链接并用 Clipper 提交：服务端去重后使用原来源 ID，
工具检查标题是否为空；有标题则保留，无标题则尝试浏览器采集。
如果网站记录存在但本机队列没有该记录，需要重新提交，不能只等待。

分类是 ResearchOS 服务端的功能，不是 Clipper 的分类模型。在兼容的服务端上，
标题回填会更新基于标题、摘要或已保存文本的自动分类建议。人工确认的标签
应由服务端保留。仅凭标题无法保证精细分类，泛化标题可以留在“拓展阅读”。

- 标题提取：不调用模型，不生成猜测标题。
- 自动标签：由网站的分类规则或已配置处理流程决定，不代表科学核验。
- 正文及 AI 总结：独立流程。只有标题不意味着大模型已经读过整篇文章。
- 新安装默认关闭 AI；用户明确启用后，新提交的链接可以按网站的既有策略处理。
  这可能调用外部付费 API，不会因为重复收藏自动重跑已完成的模型任务。

## 重启与换电脑

- `--login` 开启 Hammerspoon 登录启动。队列会在工具重启后恢复，
  已授权的本机网关也必须具有自己的登录启动配置。
- 扩展队列保存在该浏览器本地，浏览器启动后恢复。
- 电脑关机时不能使用本机浏览器取标题；登录、联网且相关程序启动后继续。
- 换电脑后重新安装工具并连接同一 ResearchOS，已入库的文章仍保留在服务器。
  **尚未提交的本机队列不会自动跨设备同步。**
- Mac 本机网关不能直接复制给另一台电脑使用；没有网关的新电脑应测试浏览器
  扩展，或由自己配置安全网关。
- 本仓库不负责服务器开机启动、Cloudflare Tunnel 或服务器迁移。

## 常见问题

**提示保存成功，为什么还没有标题？**

成功提示可能只是链接已入库。等待标题回读确认；微信验证、Chrome 权限、
网站连接失败都可能让标题任务暂缓。

**遇到微信验证怎么办？**

Mac 菜单选择“查看待验证文章”，由你完成验证；必要时选择“继续获取标题”。
工具不绕过验证码、付费墙或访问控制，也不保证每个链接都可读取。

**标题已保存，网站仍显示链接？**

刷新资料库，并检查是否选中了“链接”展示方式。网站缓存和自动刷新需要由
网站自身处理。关键词检索失败时，先核对该来源的服务器标题，不要把模型摘要
是否完成当作标题同步成功的证据。

**能否保存原文排版、图片或完整正文？**

自动标题流程不能。Mac 的可选正文补充需要你明确复制有权处理的文本并确认；
不自动抓取图片、不保证原页面排版。

**普通书签服务能直接接入吗？**

不能直接接入。需要实现下述接口与认证；本仓库不包含完整 ResearchOS 服务端。

## 服务端接口约定

Mac 客户端仅接受带端口的字面 `127.0.0.1` HTTP 地址。它必须连接到已授权、
受保护的网关，不得暴露到局域网或公网。浏览器扩展使用获准的 HTTPS 网站。

收藏请求：

```http
POST /api/v1/intake
Content-Type: application/json
```

```json
{"value":"https://mp.weixin.qq.com/s/EXAMPLE","source_kind":"wechat","ai_consent":false}
```

成功响应必须包含保存凭据和来源 ID：

```json
{"saved":true,"duplicate":false,"source_id":"12345678-1234-1234-1234-123456789abc"}
```

标题流程还需要：

- `GET /api/v1/sources/{source_id}`：返回原始链接和已保存标题。
- `POST /api/v1/sources/{source_id}/capture`：支持元数据标题回写。
- 元数据请求使用 `capture_scope: "metadata_only"`，不附带正文。
- 回写响应包含 `source_id` 与 `captured.title`；客户端再 GET 回读确认。

服务端必须实施访问控制、URL 校验、去重与来源匹配；需要抓取其他来源时，
还应防范 SSRF 并尊重访问限制。标题保护必须由服务端可靠执行，不能只依赖
客户端的先读后写检查来防止并发覆盖。安装本工具不会开放任何人的私人资料库。

## 手机微信转发收藏（开发预览，2026-10-12）

目标：微信文章转发给你管理的“收藏助手”公众号 → 官方回调送到服务器上的
接收器 → 现有 ResearchOS API → 同一个资料库。不依赖 Mac、Hammerspoon 或
本机 SSH 网关在线。重启手机不影响已入库记录。

**先验证账号条件，再部署。**本模块不能把网站变成微信好友，也不能证明微信
允许向你的公众号转发文章卡片。账号类型、接收权限和真实消息格式必须实测。
入口不可用时，回退到现有电脑收藏，或另行制作手机复制链接入口，不使用外挂。

### 计划与验收

- [x] 同一仓库、同一网站接口，不新建文章数据库。
- [x] 加密回调验签、AppID/收件账号匹配、用户白名单与时间窗口。
- [x] 链接消息提取标题；文本消息只接受一个公众号文章链接。
- [x] 持久队列、消息去重、同消息ID内容冲突拒绝、有限重试和来源回读。
- [x] 保留已有标题，只补空标题；不调用模型、不采集正文。
- [x] 本地 HTTP 闭环、公开密码协议向量与回归测试。
- [ ] 公众号账号/权限和真实手机转发格式核验。
- [ ] 服务器路径/空间、内部接口兼容性、私密配置与恢复点审计。
- [ ] 经批准配置独立 HTTPS 回调入口，微信握手、真实收藏与关键词检索。
- [ ] 实际服务重启、故障恢复与未授权用户拒绝验收。

新 Goal 创建被本会话既有未完成 Goal 阻止；此清单不冒称新 Goal 已启动。

### 标题与成功提示

只接受 AES 安全模式消息POST；签名验证后解密，校验 AppID 和收件账号。
`WECHAT_ALLOWED_OPENIDS` 为空会拒绝启动，不临时允许所有用户。

链接消息如果有真实 `Title`，在 intake 提交时带上标题与
`fill_missing_title: true`。网站必须已经支持原子“仅补空标题”接口。
文本消息只有 URL 时仍可能是“标题待获取”；本模块不猜标题、不启动电脑浏览器，
不保证服务器能抓到文章。文章卡片也不等于完整正文或图片。

新回调立即回复“已接收，等待网站入库”，不等待后台网络请求。
后台只有取得 `saved=true`、来源ID，并 GET 回读确认对应链接与标题，才能将
receipt 标为 `saved`；没有标题则为 `saved_title_pending`。
同消息重送时，已完成的 receipt 可回复“已入库”。本版**没有后台完成后的主动
微信通知**，因此不需要 AppSecret/客服消息权限；最终状态在网站查阅。

已完成条目不会重跑。瞬时断网/429/502/503/504最多三次退避重试；401、错误
回读等保留 failed，由操作者检查。重试只处理收藏，不调用或重跑付费模型。

参考：[wechatpy 消息说明](https://docs.wechatpy.org/zh-cn/stable/messages.html)、
[加密接收/回复流程](https://github.com/wechatpy/wechatpy/blob/master/docs/quickstart.rst)。
模块使用 Node 内置密码库及受限的平面 XML 解析器，不增加 SDK 依赖；测试采用
[wechatpy 公开密码格式向量](https://github.com/wechatpy/wechatpy/blob/master/tests/test_crypto.py)
验证互通格式，不仅验证自身加解密。协议测试不是微信实机验收。

### 私密配置与运行

需要 Node.js 22 或更高，无新增 npm 依赖。
`mobile/config.example.env` 中只有空白占位；正式配置放服务器私密目录：

- 回调 Token、EncodingAESKey、AppID、原始账号ID（通常 gh_ 开头）。
- 允许收藏的 OpenID（不是微信号，不公开、不贴到聊天里）。
- 既有 ResearchOS API 凭据、已授权内部API根地址、公众网站根地址。
- 经审计的服务器持久队列路径；真实队列不放 Mac、不提交 Git。

配置由服务管理器安全加载后运行：

```sh
npm run start:mobile
```

固定监听 `127.0.0.1:8791`，接口 `/wechat/callback`。
`/health` 只证明进程存活，不证明微信连通、网站认证或保存成功。
API Token 不放手机、浏览器、URL 或回调响应。

Cloudflare Access 登录页不能用于微信机器回调。正式部署需要一个专用 HTTPS
回调主机/路由，仅暴露此接口，用微信签名、加密、用户绑定和代理限流保护。
**网站与API的现有 Access/认证保持不动，不设置网站全局免登录。**
具体 DNS、Tunnel、反向代理和服务变化须审核批准，本项目不会自动执行。
代理应设置64KiB请求体上限、合理限流、短超时，并避免记录查询签名和正文。

### 自动启动与换设备

`mobile/receiver.service.example` 是未安装的 Linux user-service 模板，需审计
服务经理、绝对代码/Node/配置路径。用户服务在退出登录/主机重启后运行还需
批准的 lingering 或其他监督方式；模板不等于已配置开机启动。

接收器限单实例：锁保存PID，确认旧进程不存在后才自动移除旧锁。
正常停止等待在途请求结束再解锁。消息队列采用原子写入和 fsync；重启保留
来源ID、重试次数和 receipt。已有来源ID只重试回读；未知提交结果可能重发
intake，由网站同链接去重保护。损坏队列/锁、复用PID会停止并要求人工检查，
不能通过删除整个队列来“修复”。

总队列上限1,000条（含完成receipt）；到达上限拒绝新消息，不偷偷删除历史。
按备份/隐私规则审核归档后再继续。新微信账号需独立绑定；换手机但保留同一
绑定账号仍可使用。换服务器要迁移私密配置与队列并重新验收，不保证永久免维护。

### 上线还需要什么

当前用户已确认“有公众号，尚不清楚权限”。因此下一步是只读查看后台，不是
继续要求注册新账号。若公众号已有服务器URL/菜单/自动回复业务，先记录原配置
和影响范围；不可直接替换已有回调，需选择现有服务转发或审查后的统一接收器。

告诉操作者：是否有可管理的公众号、账号类型、后台是否有“服务器配置”。
不要发送 Token、AESKey、AppSecret、API Token 或 OpenID。
随后在服务器私密配置填写，操作者只读核对。未知 OpenID 时需另做人工批准的
一次性绑定，不能临时放开所有发送者获取身份。

最终验收：真实手机转发 → 正确标题入库 → 网站关键词搜索 → 重复转发不新增
→ 未绑定用户拒绝 → 接收服务重启后仍能工作。未完成前不宣称手机转发已可用。
